## What this is

The acceptance criterion every candidate partition must now pass, factored out of
`tmp/b1_sham_control.py` so that any partition — from any discovery run, with any number
of groups — goes through the identical procedure.

**Why the old criterion was retired.** B1 (#10) showed the published G1–G4 partition does
not beat partitions matched exactly on group size and survivor fraction. Pooled recall
measured against an *undivided* cohort cannot tell a real stratification from class
balance, so it is no longer admissible on its own as evidence that a partition works.

## What a sham is

Given a real partition, a sham shuffles the survivors and deals them into the real group
shapes, then does the same for the non-survivors. Every sham matches the real partition
**exactly** on group count, on each group's size, and on each group's survivor fraction.
No tolerance is involved. The only thing that varies is *which* patients land in which
group — precisely the contribution the discovered features are supposed to be making.

`test_shams_match_group_size_and_survivor_fraction_exactly` asserts this against
`deal_sham` directly, so the test cannot pass by re-implementing the dealing it checks.

## Scoring

A3's pooled clean-split procedure on `auth_split` (#106): per group, pick
`(threshold, direction)` on TRAIN maximising train recall subject to train precision ≥
floor; apply it unchanged to TEST; union the predicted-positive sets; compute pooled
precision and recall once over that union. A group that cannot reach the floor on train
contributes nothing rather than guessing.

## Worked example

```python
from sham_gate import evaluate, passes, published_partition, to_frame

result = evaluate(published_partition(), n_sham=2000)
print(to_frame(result).to_string(index=False))
print("gate at 0.98:", "PASS" if passes(result, 0.98) else "FAIL")
```

From the command line, at the repository root:

```bash
python filter-repository-python/sham_gate.py --n 2000
python filter-repository-python/sham_gate.py --assignment tmp/my_partition.csv --n 2000 \
    --out tmp/my_partition_gate.csv
```

`--assignment` takes any CSV with a patient id column (`patient_id` or `pid`) and a group
column (`group` or `assignment`); rows labelled `Unassigned` are dropped. `--scores`
points at a different per-patient scores file — pass the 24 h features here to score a
partition built inside the deployable window.

The draw order is deliberately identical to `tmp/b1_sham_control.py` — one survivor
permutation then one target permutation per sham, dealt in sorted group order — so a
fixed seed reproduces B1's draws bit for bit. The to-do asked for agreement "within
Monte-Carlo error"; what came out is exact.

## Two things the gate surfaces for free

**It reproduces A5's floor failure.** `meets_floor` is `False` at 0.99 and 0.98 — the
routed system does not reach its own precision floor on held-out data (94 TP, 3 FP gives
0.9691). `test_meets_floor_reproduces_the_a5_failure` pins that, so any future partition
is checked against the floor it claims, not only against the shams.

**It handles partitions that are not four groups.** A new discovery run has no obligation
to produce four. `test_handles_group_counts_other_than_four` covers 2, 3 and 6.

The exact 2000-sham reproduction is gated behind `SHAM_GATE_FULL=1` because it takes
~35 s; the default suite runs the deterministic assertions plus a 200-draw statistical
check against B1's means. Whole suite at the time of writing: **136 passed, 4 skipped**.
